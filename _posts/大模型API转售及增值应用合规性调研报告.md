# 国内主流大模型平台 API 转售及增值应用合规性调研报告

> **调研日期**：2026 年 6 月 29 日（火山引擎方舟部分补充于 2026 年 7 月 8 日，Coding Plan 与 API 聚合工具部分补充于 2026 年 7 月 8 日）  
> **调研对象**：阿里云百炼、腾讯混元、DeepSeek 开放平台、火山引擎方舟  
> **调研范围**：API/Token 转售禁止条款、增值应用许可条款、竞业限制条款、平台模型分类及服务提供方式、Coding Plan 订阅套餐使用限制及 API 聚合工具合规性

---

## 一、核心结论

**四家平台均允许基于 API 开发增值应用对外提供服务，但阿里云百炼、腾讯混元和火山引擎方舟均存在明确的转售禁止条款，DeepSeek 无此限制。其中火山引擎方舟限制最为严格——不仅禁止转售，还要求任何"商业使用"均须事先取得书面许可，且明确禁止利用服务输出进行模型蒸馏（含非竞品模型）。**

| 维度 | 阿里云百炼 | 腾讯混元 | DeepSeek | 火山引擎方舟 |
|------|:---:|:---:|:---:|:---:|
| 纯转售 API/Token | ❌ 禁止 | ❌ 禁止（六类行为全覆盖） | ⚠️ 未禁止 | ❌ 禁止（且商业使用即需书面许可） |
| 开发竞品/蒸馏模型 | ❌ 禁止 | ❌ 禁止 | ✅ 明确允许 | ❌ 禁止（蒸馏含非竞品亦禁止） |
| 集成自有应用对外服务 | ✅ 允许 | ✅ 允许 | ✅ 允许 | ⚠️ 条款存在张力（见 3.4） |
| 合规义务复杂度 | 中等（4 项） | **高（11 项）** | 高（5 条） | 高（7 项） |
| 转售唯一合法路径 | 书面许可 | 书面许可 | —（可自行开展，但需注意品牌限制） | 商业使用书面许可 |

---

## 二、调研背景

随着大模型 API 生态的成熟，越来越多的企业希望将第三方大模型能力集成到自身产品中，或作为中间平台聚合多家模型能力对外提供服务。本次调研旨在厘清国内四家主流大模型平台在 API 转售和增值应用开发两个场景下的合规边界，为企业技术架构选型和商业模式设计提供参考。

### 3.1 阿里云百炼

**适用协议**：《阿里云百炼服务协议》（2026 年 4 月 11 日生效）

**协议链接**：https://terms.alicdn.com/legal-agreement/terms/common_platform_service/20230728213935489/20230728213935489.html

#### 转售禁止 — 第 4.6 条

> 未经我们及相关权利人书面许可，您不得转售本服务及平台内模型，和/或利用本服务及平台内模型（包括模型的输出内容）训练、开发与本服务、我们及我们的关联公司提供的模型相竞争的产品或服务。

#### 增值应用允许 — 第 4.3.3 条（核心要点摘录）

> 若您利用本服务自行开发应用、对外提供服务等，作为技术支持者或服务提供者，您应自行遵守《中华人民共和国刑法》《网络安全法》《数据安全法》《个人信息保护法》《互联网信息服务管理办法》《互联网信息服务深度合成管理规定》《生成式人工智能服务管理暂行办法》等法律、行政法规及规章制度，并承诺：（1）训练数据来源合法，不侵犯他人知识产权和个人信息权益，制定清晰标注规则并开展标注质量评估；（2）不收集用户非必要个人信息，不非法留存或向他人提供用户输入信息和使用记录；（3）具有舆论属性的服务需开展安全评估和备案；（4）依法留存日志记录。

> **注**：以上仅摘录核心要点，第 4.3.3 条原文义务项数更多（如数据标注规范、用户适用人群公示等），完整合规义务请以协议原文为准。此外，第 4.3.1(3) 条还要求对利用本服务生成的非真实信息以显著方式标识（含水印、声明等），实质上构成 AI 生成内容标识义务。

**判定逻辑**：4.3.3 允许 / 4.6 禁止 → 做增值应用可以，纯转售不行。

#### 数据保护 — 《特定模型服务协议》第 3.1 条 + 《平台专用条款》第 3.7.7 条

> 服务将不使用您提交给服务或使用服务输出的内容训练、重新训练或改进基础模型。（除外情况：您主动同意《数据授权使用协议》或参与协作奖励计划）

> 未经您的单独同意，火山引擎不会存储和使用您的数据来训练或优化模型。

#### 品牌限制 — 《特定模型服务协议》第 5.3 条

> 未经火山引擎书面/邮件同意，不得在任何时候、以任何方式（无论是直接还是间接，也无论是明示还是暗示；包括但不限于任何营销、广告、促销、市场推广或其他目的）：使用、引用、公布、复制、分销、展示火山引擎或其关联方拥有或有权使用的任何商标、商号、名称、标志或者标识……及直接或间接声明您或其任何关联方所提供的任何产品或服务已由火山引擎或其任何关联方认可或支持。

**判定逻辑**：限制最严格。第 2.1 条虽允许"在产品中调用供最终用户使用"（增值应用路径存在），但平台专用条款第 3.1 条要求"商业使用需书面许可"，二者存在张力——将模型集成到自有商业产品对外收费服务，既符合第 2.1 条的"产品调用"，又可能触发第 3.1 条的"商业使用"门槛。建议商用前向火山引擎书面确认。纯转售则被第 2.1 条 + 第 2.3(1) 条明确禁止，且蒸馏行为被第 2.3(5) 条双重封堵。

## 五、平台模型分类及服务提供方式

> **时效性声明**：本节列举的模型版本号截至调研日期（2026 年 6 月 29 日），AI 模型迭代速度极快，部分模型可能已更新或下线，请以各平台最新页面为准。模型版本号仅用于说明分类逻辑，不影响本文合规分析的结论。

四家平台均托管多家厂商的模型，但模型分类逻辑、服务提供方和协议适用方式存在显著差异，直接影响合规义务的确认路径。

### 5.1 火山引擎方舟 — 三类模型、分层协议

方舟按"服务提供方式"将模型分为三类，每类适用不同协议，是四家中唯一在同一平台内按模型类别区分协议的平台。

| 类别 | 定义 | 推理服务提供方 | 适用协议 | 计费方式 | 典型模型 |
|------|------|--------------|----------|----------|----------|
| 特定模型 | 火山引擎关联公司自研、方舟售卖 | 火山引擎关联公司（字节跳动） | 《特定模型服务协议》（最严格） | 按模型定价 | Doubao-Seed-2.0-lite、Doubao-1.5-pro、Doubao-Embedding |
| 第三方专有模型 | 第三方模型服务商基于大模型提供 | 第三方模型服务商 | 各自《模型服务协议与规则》 | 按模型服务商定价 | DeepSeek-V3、DeepSeek-R1、GLM-4.7、Kimi-K2 |
| 开源模型 | 基于公开可下载的开源大模型 | 方舟自行部署 | 开源许可证 + 平台条款 | 仅收算力资源费 | DeepSeek-R1-Distill-Qwen-7B/32B、Qwen-7B |

> **分类关键**：同一厂商的模型可能分属不同类别。以 DeepSeek 为例——DeepSeek-V3/R1（满血大模型）由 DeepSeek 公司作为模型服务商提供推理，归入"第三方专有模型"；DeepSeek-R1-Distill-Qwen-7B/32B（小模型）由方舟自行部署开源权重，归入"开源模型"。分类依据是"谁提供推理服务"，而非"模型权重是否开源"。

### 5.2 阿里云百炼 — 统一协议、混合直供

百炼按"模型归属"分为自研和第三方两类，但不按模型类别区分协议，所有模型统一适用《阿里云百炼服务协议》。第三方模型存在"阿里云直供"和"第三方直供"混合渠道。

| 类别 | 推理服务提供方 | 适用协议 | 典型模型 |
|------|--------------|----------|----------|
| 自研商业版 | 阿里云 | 《阿里云百炼服务协议》（统一） | Qwen3.7-Max、Qwen3.7-Plus、Qwen3.7-Flash、万相2.6 |
| 自研开源版 | 阿里云 | 同上（统一） | Qwen3、Qwen2.5、QwQ-32B |
| 第三方模型（阿里云直供） | 阿里云自行部署 | 同上（统一） | DeepSeek（阿里云直供）、GLM（阿里云直供）、Kimi（阿里云直供） |
| 第三方模型（第三方直供） | 第三方厂商原厂提供 | 同上（统一） | DeepSeek（硅基流动直供/快手万擎直供）、Kimi（月之暗面直供）、MiniMax（稀宇科技直供） |

> **特点**：一套协议管所有模型，合规义务一致，使用最简单。但服务提供方存在混合渠道，同一模型（如 DeepSeek）可能来自不同推理提供方，实际计费可能因直供来源不同而有差异。

### 5.3 腾讯云 — 多入口、多协议

腾讯云的模型分散在不同产品线中，各入口协议和计费独立，分散程度最高。

| 入口 | 模型类别 | 推理服务提供方 | 适用协议 | 计费方式 | 典型模型 |
|------|----------|--------------|----------|----------|----------|
| 混元大模型 API（原生云 API） | 腾讯自研混元 | 腾讯云 | 《大模型服务条款》 | 按 Token 计费 | Hunyuan-T1、Hunyuan-Turbo-S、Hunyuan-Lite |
| 知识引擎原子能力（LKEAP） | 第三方专有模型 | 腾讯云代理/原厂 | LKEAP 相关条款 | 按 Token 计费 | DeepSeek-R1、DeepSeek-V3.2 |
| 智能体开发平台（ADP） | 预置模型 + 第三方接入 | 腾讯云 / 第三方厂商 | ADP 相关条款 | 按 Token 计费 | 混元、DeepSeek、百川、通义千问 |
| TI-ONE 平台 / HAI / 云应用 | 开源模型（用户自行部署） | 用户自行部署 | 开源许可证 + 平台条款 | 按算力资源计费 | DeepSeek 系列、Llama、Hunyuan-Large（开源版） |

> **特点**：自研混元走原生 API，第三方模型走 LKEAP，开源模型走 TI-ONE/HAI/云应用（用户自行部署）。每个入口有独立条款，需按入口分别确认合规义务。

### 5.4 DeepSeek 开放平台 — 单一来源

DeepSeek 平台只提供自家模型，无第三方模型，无开源/闭源区分。

| 类别 | 推理服务提供方 | 适用协议 | 计费方式 | 典型模型 |
|------|--------------|----------|----------|----------|
| 自研模型 | DeepSeek 公司 | 《DeepSeek 开放平台服务协议》 | 按 Token 计费 | DeepSeek-V3、DeepSeek-R1、DeepSeek-V4-Pro |

> **特点**：最简单——单一协议，无分层。但 DeepSeek 模型权重本身开源，用户也可通过阿里云百炼、火山方舟、腾讯云等第三方平台调用，此时适用的是相应平台的协议而非 DeepSeek 自己的协议。

### 5.5 四家平台综合对比

| 维度 | 火山引擎方舟 | 阿里云百炼 | 腾讯云 | DeepSeek 开放平台 |
|------|------|------|------|------|
| 模型分类数 | 3 类 | 2 类（自研/第三方） | 3 类（分散于多个入口） | 1 类 |
| 分类依据 | 服务提供方式 | 模型归属 | 产品入口 | 不分类 |
| 开源模型提供 | 有（独立类别，仅收算力费） | 有（与商业版同协议） | 有（TI-ONE/HAI 自部署） | 不适用 |
| 第三方模型服务方 | 第三方厂商 | 混合（阿里云直供 + 第三方直供） | 腾讯云代理 / 原厂 | 不适用 |
| 协议区分 | **按模型类别区分**（三类不同协议） | **不区分**（统一百炼协议） | **按入口区分**（各入口独立条款） | **不区分**（单一协议） |
| 合规确认复杂度 | 高（逐模型确认协议） | 低（一套协议全覆盖） | 中高（按入口确认） | 最低 |

> **合规影响**：火山方舟的"分层协议"要求最高合规成本——调用特定模型（豆包）受《特定模型服务协议》最严格条款约束，调用第三方模型需叠加原厂协议，调用开源模型需遵守开源许可证。百炼的"统一协议"对企业最友好，一次确认即可覆盖所有模型。腾讯云介于两者之间，需按入口确认，但每个入口内部相对统一。

## 六、Coding Plan 订阅套餐与 API 聚合工具合规分析

随着 AI 编程场景的普及，火山方舟、阿里云百炼、腾讯云三家平台均推出了面向个人开发者的 Coding Plan 订阅套餐（如方舟 Coding Plan、百炼 Coding Plan、腾讯云 Coding Plan），以固定月费换取大额度模型调用权限。与此同时，new-api、one-api 等开源 API 聚合网关被广泛用于统一管理多家厂商的 API Key 并对外提供服务。本节分析"购买 Coding Plan + 用 new-api 等工具聚合成统一 API 对外服务"这一模式的合规性。

### 6.1 Coding Plan 的使用限制条款

三家平台的 Coding Plan 均明确限定了使用场景——**仅限在编程工具中交互式使用，严禁用于 API 调用和对外服务**。

| 限制维度 | 火山方舟 Coding Plan | 阿里云百炼 Coding Plan | 腾讯云 Coding Plan |
|----------|----------------------|------------------------|---------------------|
| 禁止 API 调用 | ✅"不能用于 API 调用" | ✅"禁止用于自动化脚本或后端服务" | ✅"禁止以 API 调用的形式用于自动化脚本、自定义应用程序后端或任何非交互式批量调用场景" |
| 仅限编程工具交互式使用 | ✅ | ✅"仅限编程工具使用" | ✅"仅限在编程工具中使用" |
| 禁止账号共享 | — | — | ✅"为订阅人专享使用，严禁账号共享"（独有明示） |
| 仅限个人开发者 | ✅"企业级开发需求请通过 API 调用" | ✅"明确服务于个人开发者" | ✅"主要面向个人开发者" |
| API Key 数量限制 | — | — | ✅"仅支持生成一个 API Key"（独有） |
| 违规后果 | 订阅停用 + 账号封禁 | 封禁 API Key + 暂停服务 | 订阅暂停 + API Key 封禁 |

**条款原文摘录**：

> **火山方舟**（套餐概览页面）：使用限制：不能用于 API 调用。在非 AI 编程工具中使用方舟 Coding Plan 权益对应的 Base URL 和 API Key 有可能被识别为滥用/违规，会导致订阅停用或账号封禁。

> **阿里云百炼**（Coding Plan 介绍页面）：限制：仅限编程工具使用，禁止用于自动化脚本或后端服务，违者可能封禁 API Key。禁止非交互式调用：如 Postman 或脚本调用将视为违规，可能导致服务暂停。

> **腾讯云**（Coding Plan 概述页面"订阅前须知"）：严禁 API 调用：仅限在编程工具中使用，禁止以 API 调用的形式用于自动化脚本、自定义应用程序后端或任何非交互式批量调用场景。将套餐 API Key 用于允许范围之外的调用将被视为违规或滥用，可能会导致订阅被暂停或 API Key 被封禁。

此外，火山方舟《火山方舟大模型订阅套餐服务专用条款》第 2.2 条还设有"商业使用许可门槛"：

> 火山引擎服务仅限于您和（或）您的产品自行使用……如您就本服务进行商业使用或以其他方式直接或间接获得收益，则您需要事先获得火山引擎的书面许可。

### 6.2 API 聚合工具（new-api / one-api）的工作原理

new-api、one-api 等开源 API 聚合网关的核心功能包括：

1. **密钥托管**：将各家厂商的原始 API Key 集中存储在网关后台
2. **子令牌分发**：生成独立的子密钥（子令牌）供第三方使用，可设置额度、可用模型、IP 白名单等限制
3. **统一接口**：对外提供统一的 OpenAI 兼容接口（`/v1/chat/completions`），屏蔽底层厂商差异
4. **负载均衡与故障转移**：多渠道自动分流，某渠道故障时自动切换备用
5. **计费与用量统计**：记录每次调用的模型、Token 消耗、费用估算

这一机制在功能上等同于"转售 API 访问权限"——将厂商 API Key 包装后以子令牌形式提供给第三方使用。

### 6.3 违规性质分析

使用 new-api 等聚合工具将 Coding Plan 套餐对外提供服务，在三家平台均构成明确违规，具体触犯以下条款：

| 违规点 | 火山方舟 | 阿里云百炼 | 腾讯云 |
|--------|----------|------------|--------|
| 构成"API 调用" | ❌ 违反"不能用于 API 调用" | ❌ 违反"禁止用于自动化脚本或后端服务" | ❌ 违反"禁止以 API 调用的形式用于自动化脚本、自定义应用程序后端" |
| 构成"非交互式批量调用" | ❌ 网关自动转发 | ❌ 违反"禁止非交互式调用" | ❌ 违反"禁止非交互式批量调用场景" |
| 构成"账号共享" | ❌ 子令牌分发 | ❌ 子令牌分发 | ❌ 违反"严禁账号共享" |
| 构成"商业使用" | ❌ 违反第 2.2 条商业使用许可门槛 | — | — |
| 违规后果 | 订阅停用 + 账号封禁 | 封禁 API Key + 暂停服务 | 订阅暂停 + API Key 封禁 |

### 6.4 即使使用标准按量 API + 聚合工具仍有转售违规风险

即使不使用 Coding Plan，而是购买标准按量计费 API 并通过 new-api 聚合对外服务，仍然触及各平台的转售禁止条款：

| 平台 | 违反条款 | 违规行为 |
|------|----------|----------|
| 火山方舟 | 《特定模型服务协议》第 2.1 条 + 平台专用条款第 3.1 条 | "不得以任何方式向第三方单独提供" + "商业使用需书面许可" |
| 阿里云百炼 | 《百炼服务协议》第 4.6 条 | "不得转售本服务及平台内模型" |
| 腾讯云 | 《大模型服务条款》第 2.6(6) 条 | "不得通过出租、出借、出售、分销、转售或转让等方式向第三方提供本服务或 API Token" |
| DeepSeek | 无转售禁止条款 | 不违规（但仍需注意第 5.3 条品牌限制） |

new-api 的"子令牌分发"机制本质上是"分销"和"转售"API Token 的行为，正是各平台转售禁止条款所封堵的对象。

### 6.5 各场景合规路径汇总

| 场景 | 火山方舟 | 阿里云百炼 | 腾讯云 | DeepSeek |
|------|----------|------------|--------|----------|
| Coding Plan 自用编程 | ✅ 合规 | ✅ 合规 | ✅ 合规 | — |
| Coding Plan + new-api 对外 | ❌ 违规（禁 API 调用 + 禁商业使用） | ❌ 违规（禁 API 调用 + 禁自动化） | ❌ 违规（禁 API 调用 + 禁账号共享） | — |
| 标准 API + new-api 对外 | ❌ 违规（转售禁止 + 商业许可门槛） | ❌ 违规（转售禁止） | ❌ 违规（转售禁止） | ✅ 不违规 |
| 标准 API 集成自有产品 | ✅ 合规（但商业使用建议书面确认） | ✅ 合规 | ✅ 合规 | ✅ 合规 |
| 多模型聚合转售平台 | ❌ 需书面许可 | ❌ 需书面许可 | ❌ 需书面许可 | ✅ 可行（注意品牌限制） |

> **结论**：Coding Plan 的设计初衷是"个人开发者在编程工具中的交互式使用"，用 new-api 等聚合工具对外服务从产品设计层面就超出了授权范围。即使使用标准 API，new-api 的"子令牌分发"机制也触及转售禁止条款。唯一无明显条款障碍的是基于 DeepSeek 标准 API 做聚合服务，但仍需严格规避品牌使用。

## 七、风险提示

1. **协议动态更新风险**：四家平台的协议均保留了单方更新权利，上述条款可能随时变更，正式商业决策前务必核实最新版本。

2. **DeepSeek 的品牌陷阱**：虽无转售禁令，但第 5.3 条的品牌限制极为严格，任何暗示"官方代理/合作"关系的行为均构成根本违约，后果包括终止协议且不退余额。

3. **腾讯条款覆盖面最广**：即使不"转售"，通过"出租""出借""分销"等形式提供 API Token 同样违反第 2.6(6) 条。

4. **火山引擎的"商业使用许可"门槛**：《火山方舟专用条款》第 3.1 条要求任何"商业使用或以其他方式直接或间接获得收益"均须事先取得书面许可，这与《特定模型服务协议》第 2.1 条允许"在产品中调用供最终用户使用"之间存在张力。增值应用商业化前，建议向火山引擎书面确认是否触发许可义务，避免被认定超出授权范围而遭终止服务。

5. **火山引擎的蒸馏禁令最严格**：第 2.3(5) 条不仅禁止训练竞品模型，还禁止利用服务输出训练/微调"任何"其他模型，覆盖面广于阿里、腾讯（两者仅限竞品范畴）。任何基于豆包等模型输出的蒸馏、微调行为均存在违约风险。

6. **增值应用与转售的边界**：四家均未给出精确的定量判断标准（如"多少行代码算增值加工"），存在一定解释空间，极端情况下建议向平台方书面确认。

7. **跨平台调用同一模型的协议差异**：同一模型（如 DeepSeek-V3）在不同平台上的适用协议不同——在 DeepSeek 开放平台适用 DeepSeek 协议，在火山方舟适用方舟平台条款 + DeepSeek 模型服务协议，在阿里云百炼统一适用百炼协议。跨平台迁移时需重新确认合规义务，不可直接套用。

8. **火山方舟分层协议的合规盲区**：方舟是四家中唯一在同一平台内按模型类别区分协议的平台，调用不同模型需确认不同协议，易出现遗漏。尤其是从"第三方专有模型"切换到"特定模型"（豆包）时，协议从原厂条款变为《特定模型服务协议》，转售禁止、蒸馏禁止等限制显著加严。

9. **Coding Plan 不可用于 API 聚合对外服务**：三家平台的 Coding Plan 均明确禁止用于 API 调用、自动化脚本和后端服务，用 new-api、one-api 等聚合工具将 Coding Plan 对外服务属于明确违规，后果包括订阅停用、API Key 封禁乃至账号封禁。即使使用标准按量 API，聚合工具的"子令牌分发"机制也触及转售禁止条款。

## 八、建议

1. **若仅需 API 集成到自有产品**：DeepSeek 条款阻力最小；阿里、腾讯均明确允许；火山引擎方舟需特别注意"商业使用书面许可"门槛，建议商用前书面确认。
2. **若计划做多模型聚合/转售平台**：DeepSeek 是唯一无明显条款障碍的选择，但需严格规避品牌侵权；阿里、腾讯必须获取书面许可；火山引擎方舟因"商业使用许可"门槛，聚合转售模式阻力最大。
3. **若需"官方代理"资质**：四家均需直接联系厂商走商务合作流程，无协议层面的自动许可。
4. **若涉及模型蒸馏/二次训练**：仅 DeepSeek 明确允许；阿里、腾讯限竞品范畴；火山引擎方舟全面禁止（含非竞品），需特别注意。
5. **合规底线（四平台共通要求）**：算法备案 + 安全评估（如涉及舆论属性）+ AI 生成内容标识 + 内容安全审核。火山引擎方舟额外明示要求"监测预警"和"应急处置"机制。
6. **模型选型与协议确认**：火山方舟需按模型类别分别确认协议（特定模型/第三方/开源），合规成本最高；阿里云百炼一套协议全覆盖，合规最简；腾讯云按入口确认，居中。跨平台调用同一模型（如 DeepSeek）时，适用协议因平台而异，不可混用。
7. **Coding Plan 仅限个人编程自用**：三家平台的 Coding Plan 均明确禁止用于 API 调用、自动化脚本、后端服务和非交互式批量场景，违规将导致订阅停用或账号封禁。切勿将 Coding Plan 的 API Key 接入 new-api、one-api 等聚合网关对外提供服务。
8. **API 聚合工具的合规边界**：new-api、one-api 等工具的"子令牌分发"机制本质构成"转售/分销"API Token，在火山方舟、阿里云百炼、腾讯云三家均违反转售禁止条款。仅基于 DeepSeek 标准 API 做聚合服务无明显条款障碍，但需严格规避品牌使用。企业内部用于统一管理自有 API Key（不对外分发子令牌）的用途，合规风险较低，但仍需确认各平台对"内部使用"的界定。
